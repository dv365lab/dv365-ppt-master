# 本地网页界面

网页通过已配置的 Agnes 模型完成资料理解、大纲规划、页面生成和讲稿制作，再调用本项目的质量检查器与导出器生成原生可编辑 PPTX。无需安装或登录 Codex CLI。

## 一键启动

双击仓库根目录的 [`start-web.bat`](../../start-web.bat)。启动器检查 Python 和 Flask，启动本地服务并打开浏览器。默认地址为 `http://127.0.0.1:8765`；端口已占用时自动寻找下一可用端口，如果附近端口均被占用则由系统分配端口。浏览器会打开实际地址，也可以查看启动窗口中的地址。再次双击会打开同一个运行中的服务。

启动窗口需要保持打开。任务完成后，按 `Ctrl+C` 停止服务。升级前先等待当前任务结束，避免中断生成。服务仅监听本机地址，不需要前端构建、域名或部署。

启动器优先使用仓库中的 `.venv\Scripts\python.exe`，其次检查 `python` 和 `py -3`，要求 Python 3.10+。缺少依赖时，使用窗口显示的解释器安装：

```powershell
python -m pip install -r "F:\try\ppt-master\requirements.txt"
```

## 模型配置

默认使用 `agnes-2.5-flash`，兼容接口地址为 `https://apihub.agnes-ai.com/v1`。密钥单独保存在当前用户主目录下的 `.ppt-master/web-gui-provider.json`，不进入仓库、浏览器响应、进程参数或项目日志。

配置结构如下，替换示例密钥后保存到上述私有路径：

```json
{
  "api_key": "YOUR_API_KEY",
  "base_url": "https://apihub.agnes-ai.com/v1",
  "model": "agnes-2.5-flash"
}
```

也支持环境变量 `PPT_MASTER_LLM_API_KEY`、`PPT_MASTER_LLM_BASE_URL`、`PPT_MASTER_LLM_MODEL`；它们优先于配置文件。`PPT_MASTER_PROVIDER_CONFIG` 可指定另一个私有配置文件。

网页显示“已配置”表示配置可读取，生成时才验证服务连接和模型权限。输入内容及附件提取的正文会发送到配置的模型服务；图片附件按需发送给模型识别文字与可见图形；单张识别图片上限为 20 MB。

## 输入与页数

可以输入主题、粘贴正文、上传附件，或组合使用；只有附件也可以生成。支持文本、Markdown、CSV/TSV、PDF、DOCX、PPTX、XLSX/XLSM，以及常见图片。旧版 DOC 转换依赖 Pandoc。纯扫描 PDF 没有文字层时会明确提示，可改传可搜索 PDF 或清晰页面图片。

| 页数模式 | 行为 |
|---|---|
| 自动规划（默认） | 根据内容复杂度与信息密度选择 5–30 页，并说明规划理由。 |
| 固定页数 | 严格生成指定的 1–40 页。 |
| 页数范围 | 在指定的最小、最大页数内规划，两者均在 1–40 之间。 |

页数包含封面、目录、正文与结尾。短演示不强塞目录和过渡页。分析深度控制分块大小：简明为 1,500 字符，标准为 3,000，深入为 4,000；相邻块保留最多 200 字符重叠。长度单位是字符，不是模型 token；不同设置侧重内容详略，不承诺处理速度，小块可能需要更多模型调用。

一次最多上传 20 个文件，整体请求不超过 100 MB。资料转换失败或没有可读内容时停止并显示原因，不静默忽略该附件。

## 完整制作流程

1. 将附件转换成完整正文或 Markdown，保留原件和来源清单；用户输入也参与规划。
2. 按段落和自然停顿分块，记录原文的起止位置与每块编号，避免遗漏末尾内容。
3. 分析第一份实际资料的首块结构，再生成初始完整大纲。
4. 对其余每块依次更新完整大纲，保留之前有效的内容及引用，允许合并、拆分和重组页面。
5. 大纲调用启用模型原生 JSON 模式，每轮再进行 JSON 提取、字段标准化和严格校验，包括页数、连续页码、内容点、来源引用与 notes。
6. 保留上传图片及转换正文中可用的本地插图，Agnes 根据页面内容选择使用，再生成逐页 SVG；长演示在第 5 页后先检查一次，全部生成后做最终质量检查。可确定的分组边界标记按测量结果校正，其余问题回传给模型修复；两轮仍未通过时，提供经文字测量的简洁版式约束，由 Agnes 重建该页。备用版式依次尝试常规间距、紧凑间距和双栏，保持正文至少 22 px，并保留完整要点及阅读顺序，重建后再通过同一检查器。
7. 对照最终通过检查的 SVG 校正每页讲稿，生成 `notes/total.md` 并拆成与 SVG 一一对应的备注文件。
8. 使用 `--quick-generate --with-notes` 导出 PPTX，核验实际页数及每页非空备注；符合条件后才显示完成。

没有附件且输入较短时使用独立的主题大纲 prompt；长正文或附件走分块流程。主题模式不会冒充已经进行网络调研，也不会编造实时统计或引用。

网页中可以查看实际阶段进度、内容大纲、页数规划理由、逐页备注和幻灯片预览，并下载 PPTX、大纲 JSON 与讲稿 Markdown。停止制作会结束本次生成进程及其子进程。

## 错误恢复与重试

网络异常、限流和临时服务错误最多尝试 3 次；限流优先遵循服务的 Retry-After，没有提示时分别等待 20 和 40 秒，单次等待最多 60 秒。鉴权失败立即提示修复配置。结构分析、初始大纲、逐块细化或主题大纲返回不完整结果时，实际执行错误恢复 prompt，再按具体校验错误执行 JSON 修复，最多两轮。

修复失败后保留原资料和可用的中间结果，并将任务标为失败。不会跳过失败的材料块、凭空填充页面或把占位大纲当成成功结果。可恢复的大纲快照保存在 `analysis/outline.partial.json`；失败输出与校验详情保存在 `analysis/outline.invalid.txt` 和 `analysis/outline.errors.json`。修复原因后可从网页重新生成；重新生成会重新读取资料并规划完整大纲。

逐页讲稿生成后立即保存，后续某页失败不会丢掉已完成讲稿。已有页面和备注在重新制作时移入项目 `backup/`，先前导出的 PPTX 仍保留在 `exports/`。历史项目保留其原先指定的固定页数。

## 文件位置

```text
projects/<项目名>/
├── sources/                      原始附件
├── analysis/source_markdown/      完整正文及转换记录
├── analysis/source_manifest.json 来源、分块与字符区间
├── analysis/outline.json          最终大纲及每页讲稿
├── svg_output/                    可编辑页面源文件
├── notes/total.md                 完整讲稿
├── notes/01_slide.md              与每页对应的讲稿
├── validation/                    页面质量检查报告
├── exports/                       成品 PPTX
└── .web_gui/                      需求、任务状态和不含密钥的日志
```

## 命令行启动

```powershell
& "F:\try\ppt-master\start-web.bat" --port 8765 --no-browser
```

或者指定项目存放位置：

```powershell
python "F:\try\ppt-master\skills\ppt-master\scripts\web_gui\server.py" --projects-dir "F:\演示文稿项目"
```

`--no-browser` 只关闭自动打开浏览器的行为。实际流程参考用户提供的 `ppt-outline-extraction` 源码快照 `5a655f52037c91b5545d2ea49f43fae34472d368`，在本项目内实现，不依赖该外部目录运行。
